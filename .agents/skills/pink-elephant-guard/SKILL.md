# Pink Elephant Guard / ピンクの象ガード

却下・削除・訂正・禁止された要素を変更履歴として隔離し、現在の確定状態だけから自然な完成物を組み直す。

目標は、禁止語を伏せたり否定形で残したりすることではない。削除跡や言い訳を見せず、現在案だけで自立した完成物にする。

詳細な設計根拠、媒体別の例、実測済みテスト、既知の限界を確認する必要がある場合は、[Pink Elephant Guard ピンクの象ガード仕様書.md](<references/Pink Elephant Guard ピンクの象ガード仕様書.md>) を読む。

## 発動判定

次の3条件をすべて満たすときに使う。

1. 会話内に、却下・削除・訂正・禁止された要素がある。
2. ユーザーが、鑑賞者または利用者向けの完成物を新規作成または修正しようとしている。
3. 完成物で、その履歴を説明する必要がない。

文字列一致だけでなく、依頼全体の意味から判断する。

比較、議事録、監査、原因調査、変更履歴、法令・契約上の開示、安全・医療・アレルゲン・リスク説明、アクセシビリティ表示、再発防止、ユーザー指定の不使用訴求では暗黙発動しない。事実、失敗、危険、義務的な表示を見栄えのために隠してはならない。

判断が競合するときは、次の順で優先する。

1. 法令、安全、契約、アクセシビリティ上の必要表示
2. ユーザーが完成面へ明示するよう指定した内容
3. ユーザーが最後に確定した現在状態
4. それ以前の案や変更履歴

## 入力を分離する

制作前に、会話を内部で次の4区分へ整理する。

- `TARGET_STATE`: 修正後に存在し、伝えるべき現在状態
- `REJECTED_HISTORY`: 取り下げた案、削除対象、誤り、修正理由
- `VISIBLE_EXCEPTIONS`: 完成面へ残す必要がある比較、開示、不使用訴求
- `SURFACE`: 見出し、本文、台詞、画像、UI、ナレーションなど受け手が見る範囲

不在自体を訴求するかどうかで完成物が大きく変わり、会話から判断できない場合だけ質問する。それ以外は現在状態を優先する。

## Clean Briefから再生成する

1. `TARGET_STATE`、許可された事実、媒体、トーン、必要な構造だけで内部用のClean Briefを作る。
2. 「Xを出さない」ではなく、Xがなくても成立する肯定形で記述する。
3. 削除後の空白を、目的に合う内容、構図、動作、情報階層で埋める。
4. 却下理由や元案をClean Briefへ再投入しない。
5. 修正前の成果物から数語を削るのではなく、Clean Briefを正本として最初から組み直す。

## Pink Elephant Scan

完成前に `SURFACE` 全体を次の5層で確認する。

- Literal leak: 却下語、表記揺れ、画像内文字、ラベルが残っていないか。
- Semantic leak: 同義語、上位語、言い換え、否定形、婉曲表現で意味が残っていないか。
- Rationale leak: 削除理由、「代わりに」「以前は」などの変更説明が紛れていないか。
- Attention leak: 不在や比較が見出し、冒頭、CTA、結論の主題になっていないか。
- Visual leak: 削除物の輪郭、破片、影、容器、持ち手、プレースホルダーなどが残っていないか。

`VISIBLE_EXCEPTIONS` は、指定された場所・目的・範囲でのみ保持する。

FAILの場合、漏れた語だけを消して修理しない。Clean Briefから成果物を再生成し、Scanをやり直す。

## 媒体別の注意

- 文章: 見出し、冒頭、本文、CTA、脚注まで確認する。差分報告を求められていない完成面へ変更経緯を出さない。
- 画像生成: 現在必要な被写体、形、配置、素材、光、接触関係を肯定形で記述する。却下物を長いnegative promptとして再列挙しない。
- 動画生成: 現在必要な被写体、因果、動作、カメラ、編集、音、文字、最終フレームを定義する。旧案を「起こらない出来事」として脚本へ残さない。
- UI: 非表示にした機能名を空欄、無効ラベル、プレースホルダーとして残さない。必要なエラー、安全表示、状態説明は保持する。
- 画像や動画の実ファイルを確認していない場合、画素・フレーム・音声上の残留を検査済みと報告しない。

## 完了条件

- `VISIBLE_EXCEPTIONS` にない却下要素の語句・意味・視覚的な名残がない。
- 削除理由、変更説明、不在の強調がない。
- タイトル、冒頭、CTA、結論が現在の目的を主題にしている。
- 例外表示が指定範囲を越えていない。
- 未確認の媒体を検査済みと報告していない。
- 完成物が削除跡に見えず、`TARGET_STATE` だけで自然に成立している。

ユーザーが「完成稿だけ」と指定した場合、検査報告を添えない。
